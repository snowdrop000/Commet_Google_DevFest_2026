# Geminiによる評価・報酬・育成

## 評価と報酬

Geminiが安全性4項目と貢献度4項目を各0〜2で採点し、サーバーがS・Qと報酬を計算する。Cloud Natural Language APIは使用しない。

- `S = 2 − max(人格攻撃, 差別, 脅迫・暴力, 嫌がらせ)`。高いほど安全。
- `Q = max(感謝・応援, 建設的な議論, 質問・情報提供, ユーモア)`。
- 安全：S=2、確信度8以上、文脈十分。
- 有害：S=0、確信度8以上、文脈十分。対象・直接攻撃・本文中の根拠を確認でき、引用ではない。
- それ以外は要確認。実験と同じ暫定基準であり、暴力への賛同などが要確認になる課題は残る。

| 最終判定       | Q=0      | Q=1        | Q=2         |
| -------------- | -------- | ---------- | ----------- |
| 安全           | 2XP・1倍 | 6XP・1.5倍 | 10XP・1.5倍 |
| 有害           | 0XP・0倍 | 0XP・0倍   | 0XP・0倍    |
| 要確認（暫定） | 2XP・1倍 | 2XP・1倍   | 2XP・1倍    |

投稿成功の確認後だけ、サーバーに保存した評価からXPとコインを確定する。獲得コインは探索中の仮コイン×倍率の端数切り捨て。未投稿で探索を終了した場合の1倍精算は維持する。

API失敗・出力形式の不正・投稿成功の証拠不足は「要確認」という評価とは別で、暫定報酬を付けない。既存の保留処理を維持する。チェックだけでは報酬や成長履歴を記録しない。同じ精算を再送しても二重加算しない。

## 育成

- 初期Lv.1、XP0、ぬくもり・ひらめき・おちゃめは各10。最大Lv.99、各能力の上限300。
- 次のレベルに必要なXPは `10 + 2 × floor(現在Lv / 10)`。余りは繰り越す。Lv.1→99は合計1,862XP。Lv.99ではXPを0としてMAX表示する。
- 投稿時はXPだけを増やし、安全と確定した投稿の貢献内訳を累積する。要確認・有害の内訳は累積しない。
- ぬくもりの傾向＝感謝・応援。ひらめきの傾向＝**投稿ごとに**建設的な議論と情報提供の最大値。おちゃめの傾向＝ユーモア。
- レベルアップ時に全能力＋2。さらに累積した傾向の比率で合計3ポイントを配分する。傾向がすべて0なら追加配分なし。集計はレベルアップで消費・リセットしない。
- 配分の端数は持ち越し、能力値の増分は整数にする。上限を超えた分は切り捨て、他の能力に移さない。
- コメント本文・判定理由・引用された原文はFirestoreに保存しない。精算用の数値・フラグと、固定サイズの集計だけを保存する。

## 移行と保持するもの

旧アカウントは、新APIで最初に読み書きした際にトランザクションで一度だけ育成を初期化する（`growthVersion=1`）。初期化対象はレベル・XP・3能力・新しい貢献集計のみ。投稿数・連続日数・既存の実績カウンターは保持する。

キャラの種類・名前・見た目・装備・全所持品・解放済みアイテム・コイン・ガチャ履歴・かけら・旧キャラの保存情報は保持する。古い所持品整理が育成移行に伴って走らないよう、既存の所持品を所持済みとして扱う。旧形式の評価記録から新しい報酬は付与しない。

内部の能力フィールド名は既存の `empathy / criticalThinking / resilience` を継続し、表示名と成長元を新制度に合わせる。既存のアイテム定義・解放条件・称号・ガチャ・キャラ素材は変更しない。既存の実績カウンターは新評価の該当要素から更新する。称号と解放条件の再設計は別担当として保留する。
