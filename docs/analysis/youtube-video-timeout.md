# 長時間YouTube動画の要約が使われなかった原因

確認日：2026年11月9日

## 症状

利用者のGoogleログインと着せ替え保存は成功したが、動画のコメント判定に「動画要約を考慮」が表示されなかった。対象は公開動画`https://www.youtube.com/watch?v=PF630-XnjiE`。文脈の利用・動画要約の設定は両方有効だった。

## 原因と実測

以前のサービスID未初期化による401とは別の問題。動画要約と短いコメント判定に同じ10秒のタイムアウトを適用していた。要約が時間切れになると、既存処理はタイトル・説明文へ切り替えてHTTP 200を返す。そのためコメント判定自体は成功していた。

- YouTubeの公開メタデータで、対象動画は3,933秒（65分33秒）と確認した。
- 対象URLをアプリの動画要約コードへ渡すと、従来設定では約10,152msで`TimeoutError`になった。
- 診断時の待ち時間を延ばすと、HTTP 200・JSONスキーマ検証成功になった。最初の成功は約35,366msで、要約は629文字。
- 60秒で打ち切られる場合もあったため、動画用の上限は120秒とした。処理時間にはばらつきがあり、常に35秒以内に完了するとは限らない。
- 修正後のAPIで、同じ動画の要約とコメント判定が約30,952msで完了し、`videoSource: "gemini_video"`を確認した。この結合確認はローカルFirebase Emulatorと実際のVertex AIを使って行った。本番利用者の認証情報は取得していない。
- その後の本番試行では、`operation: "comment"`・`reason: "timeout"`・`elapsedMs: 10007`を記録した。動画用だけを延長した時点では、コメント判定の10秒制限が残っていた。この点を修正し、全体の待ち時間も再計算した。

## 修正

| 処理 | 修正前 | 修正後 |
| --- | --- | --- |
| Geminiの動画要約 | 10秒 | 120秒 |
| Geminiのコメント判定 | 10秒 | 60秒 |
| 拡張の判定リクエスト全体 | 24秒 | 210秒 |
| 通常のAPI操作 | 5秒 | 5秒 |
| Cloud Runのリクエスト上限 | 60秒 | 240秒 |

時間制限は`shared/request-timeouts.ts`で共有する。動画要約とコメント判定は順番に実行されるため、拡張側には認証・Firestore・コールドスタート分も含めた余裕を持たせた。

長い動画の処理負荷を抑えるため、要約用の映像は`videoMetadata.fps: 0.2`（5秒間隔）で取得する。開始・終了時刻を指定していないので全区間を対象とし、音声も全区間を使う。瞬間的な映像の細部を検出する処理ではなく、全体の文脈要約向けの設定。モデルが文字数・項目数の上限を超えた場合は既存の制限内へ整形するが、不正な型・予期しないフィールドは引き続き拒否する。

Chrome Manifest V3のサービスワーカーは長い待機中に終了することがある。公式の方法に従って、判定リクエストの間だけ20秒間隔で軽量な拡張APIを呼ぶ。成功・失敗の両方でタイマーを止め、無期限には維持しない。

判定結果が`page_metadata`の場合は「動画タイトル・説明文を考慮」と表示する。`gemini_video`の場合は従来通り「動画要約を考慮」と表示する。動画の取得可否をHTTP 200だけで判断しない。

失敗時は種別・HTTPステータス・処理時間だけをサーバーログへ記録する。コメント本文・動画URL・モデルの出力・認証情報は記録しない。

## 検証と反映

- 偽の時計で70秒の動画要約、35秒のコメント判定、195秒の判定応答を再現し、従来の時間制限を超えて完了する回帰テストを追加。コメントが60秒で中断されることも確認。
- 通常APIが5秒でタイムアウトすることと、拡張の継続タイマーが成功・失敗後に停止することを確認。
- 93件のAPI等のテスト、型検査、Lint、API・拡張ビルドが成功。
- ブラウザで、タイトル・説明文を使う場合の参照元表示を確認。
- 実際のブラウザでも35秒遅延する応答を待ち、拡張の結果画面まで表示できることを確認。
- 最終修正後のAPIと実際のVertex AIで、対象動画の要約を使う判定が約51,446msで成功し、`gemini_video`を確認。
- 本番リビジョン`commet-api-00004-jwg`と、本番用拡張`.output/chrome-mv3-cloud`へ反映済み。

利用者側では`chrome://extensions`でCommetを再読み込みし、YouTubeのタブも再読み込みしてから再判定する。拡張IDは変更していない。実際に動画を使えたかは、結果の「動画要約を考慮」で確認する。

第4リビジョンと修正版拡張への更新後、利用者本人から、同じ動画で判定が成功し「動画要約を考慮」と表示されたことを確認した。本番での再確認まで完了。
